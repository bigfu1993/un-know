# 佚名管理端项目开发文档

> 更新时间：2026-07-08
> 项目根目录：`D:\code\un-know`
> 目录定位：`frontend/admin` 仅承载平台 Web 管理系统项目，面向平台管理角色，与 `frontend/apps/h5`、`frontend/apps/miniapp` 同级。
> 依据：`../../../docs/admin-plan.md`、`../../../docs/client-plan.md`、`../../../docs/业务链路图.md`。

## 1. 技术方案结论

管理端第一版已确认采用：

| 层 | 推荐技术 | 说明 |
| --- | --- | --- |
| 框架 | `React + Vite + TypeScript` | 与用户端同属 React/TypeScript 技术栈，方便共享接口类型和业务规则 |
| UI 组件 | `Ant Design` | 适合表格、表单、弹窗、审核、筛选、分页等后台场景 |
| 状态管理 | `Zustand + TanStack Query` | Zustand 管理登录态、权限、菜单和筛选条件；TanStack Query 管理服务端数据 |
| 路由 | `React Router` | 按平台管理模块组织路由和权限 |
| 请求层 | `ofetch/axios 封装` | 统一 token、错误码、审计追踪、操作结果提示 |
| 图表 | `ECharts` | 数据看板、审核效率、经营指标 |
| 接口契约 | `OpenAPI + TypeScript SDK` | 管理端不手写接口类型 |

核心判断：管理端是平台运营、审核、对接、复核和配置工具，不和用户端 Web/小程序代码耦合在同一个 app 里。它作为 `frontend/admin` 下的独立 Web 管理项目开发和部署，使用 React 技术栈，避免移动端跨端适配逻辑污染管理端工程；构建产物、部署方式仍与 `frontend/apps/h5`、`frontend/apps/miniapp` 完全分开。

接口 SDK、后台枚举等共享代码优先复用 `frontend/apps/packages/api-client`、`frontend/apps/packages/domain` 等既有共享包；确有管理端专属且无法复用的类型，再评估是否新增独立包。

第一版可先只建 `src` 及配置文件，共享包按需扩展现有 `frontend/apps/packages/*`。

## 2.1 React 统一约束

- 管理端所有新增代码使用 TypeScript。
- 页面层使用 React 函数组件和 hooks。
- 表格、表单、弹窗、抽屉、消息提示优先使用 Ant Design。
- 服务端数据使用 TanStack Query，不在组件内手写 loading/error 状态散落逻辑。
- 登录态、菜单折叠、权限缓存、筛选草稿等端侧状态使用 Zustand。
- API 类型来自 OpenAPI SDK，页面不得复制接口类型。

## 3. 管理端模块

Web 管理端只允许平台管理角色登录。

| 模块 | 第一版职责 |
| --- | --- |
| 工作台 | 汇总审核、对接、复核、异常待办 |
| 审核中心 | 商品、兼职、回收、家教、校园服务、举报审核 |
| 对接中心 | 处理审核后需要人工推进的事项 |
| 校园信息管理 | 学校、校区、楼栋、楼层、活动区域、位置块 |
| 商户管理 | 商户认证、门店、状态、信用金、子账号风险 |
| 商品管理 | 平台自营、耗材、商户商品审核和上下架 |
| 兼职管理 | 商户兼职审核、报名、签到、结算、保证金 |
| 校园服务管理 | 委托发布、领取、报价、激活、履约、异常 |
| 狩猎服务方管理 | 学生认证、二次验证、押金、信用事件 |
| 家教需求管理 | 家教审核、报名查看、对接、费用结算 |
| 资金账户管理 | 钱包、观察期、提现、退款、保证金、流水 |
| 举报中心 | 内容、商品、服务、账号举报处理 |
| 配置中心 | 分类、字段、敏感词、审核模板、规则开关 |
| 数据看板 | 审核效率、商户经营、交易、兼职、校园服务数据 |

## 4. 页面设计原则

管理端是工作台型产品，优先效率和确定性：

- 使用紧凑表格、筛选条、状态标签、抽屉详情和确认弹窗。
- 不做营销式首页，不做大面积装饰。
- 审核类页面保持统一结构：基础信息、提交资料、历史记录、风险提示、审核动作、备注。
- 资金类页面必须突出金额、流水号、状态、关联业务单、处理人和时间。
- 所有高风险动作必须二次确认。
- 所有状态操作必须展示后端返回的状态变更结果。
- 管理端不直接写死业务枚举，枚举由接口或共享包提供。

## 5. 权限与角色

第一版至少预留以下平台管理角色：

| 角色 | 权限范围 |
| --- | --- |
| 超级管理员 | 全部模块、权限配置、敏感资料查看 |
| 审核员 | 审核中心、举报中心、基础对接记录 |
| 对接员 | 对接中心、订单/回收/家教/校园服务跟进 |
| 质检员 | 回收质检、商品入库、质检记录 |
| 客服 | 售后、投诉、消息、平台联系入口 |
| 财务 | 资金账户、提现、退款、保证金、流水 |
| 运营 | 校园信息、配置中心、数据看板、商品运营 |

第一版可以先实现超级管理员和通用平台管理员，但页面和接口要预留权限点。

## 6. 关键模块实现要点

### 6.1 工作台

展示：

- 待审核商户
- 待审核商品
- 待审核兼职
- 待审核家教需求
- 待审核回收单
- 待审核校园服务需求
- 待处理售后/投诉
- 待处理资金异常

交互：

- 点击卡片进入对应列表并带入筛选条件。
- 待办列表按紧急程度、超时风险、业务类型排序。

### 6.2 审核中心

统一审核动作：

- 通过
- 拒绝
- 需补充
- 转对接
- 下架/冻结

详情字段：

- 提交人/提交主体
- 所属角色
- 业务类型
- 提交内容
- 上传资料
- 风险提示
- 历史审核记录
- 审核备注

### 6.3 校园信息管理

维护：

- 学校
- 校区
- 楼栋
- 楼层
- 快递站
- 食堂
- 图书馆
- 校门
- 活动中心
- 常用位置块

自定义位置只作为兜底输入，管理端需要保留原文，方便后续标准化。

### 6.4 商户管理

处理：

- 商户类型：校园店铺、个人商户、校外服务商、校企合作
- 营业执照
- 门店照片
- 认证状态：待提交、审核中、需补充、通过、拒绝、冻结、监管
- 店铺信用金
- 多门店
- 员工子账号风险

### 6.5 商品与订单

处理：

- 平台自营闲置
- 平台自营耗材
- 商户商品
- 商户服务
- 商品审核
- 上下架
- 隐藏
- 库存、限购、售价、售卖时间
- 订单履约异常
- 售后投诉

家长端商品只允许快递配送，审核和上架时需要校验配送能力。

### 6.6 兼职管理

处理：

- 商户兼职发布审核
- 普通兼职 10 分钟默认通过倒计时
- 报名表快捷字段和自定义字段
- 报名名单
- 筛选确认
- 签到方式
- 签到保证金
- 完成确认
- 结算
- 举报/评价

### 6.7 委托/狩猎管理

处理：

- 委托发布记录
- 报价发布和服务发布
- 狩猎资格验证：身份证照片、学信网截图
- 狩猎押金
- 委托时效
- 过期领取后的确认激活
- 接单/报价锁单
- 履约异常
- 结算观察期

### 6.8 家教管理

处理：

- 家长孩子档案快照
- 家教需求审核
- 试课信息
- 报名学生资料
- 家长筛选和拒绝理由
- 电话交换记录
- 教育服务中
- 改约、终止、爽约双方确认
- 按实际服务天数占比结算

### 6.9 资金账户管理

处理：

- 用户钱包
- 商户钱包
- 可提现余额
- 观察期账户
- 押金
- 签到保证金
- 店铺信用金
- 提现申请
- 退款单
- 资金流水

第一版只做记录查看、类型筛选和关键操作审核，不展开复杂资金对账。

## 7. 第一阶段开发顺序

1. 工程初始化、登录、权限、基础布局。
2. 工作台和审核中心。
3. 校园信息管理。
4. 商户管理和商品审核。
5. 商品订单、售后、投诉入口。
6. 兼职管理。
7. 委托/狩猎管理。
8. 家教需求管理。
9. 资金账户管理。
10. 配置中心和数据看板。

## 8. 验收标准

- 平台管理人员可以登录管理端并进入工作台。
- 工作台能看到审核、对接、复核和资金异常待办。
- 审核中心能处理通过、拒绝、需补充、转对接。
- 所有操作有状态回流、提示和审计记录。
- 校园信息可维护并被用户端发布位置复用。
- 资金、举报、售后、冻结等高风险动作有二次确认。
