## 1. 产品概述

佚名是面向校园场景的多角色交易与服务平台，当前覆盖学生、商户、家长三类客户端角色。产品围绕校园优选商品/服务、兼职、委托/狩猎、家教招募、钱包、订单、账户资料和商户经营工作台建立第一阶段移动端体验。

当前阶段目标是完成多角色移动端产品骨架、登录注册链路、角色路由、关键模块页面展示、资料补充校验、购买确认、工作台数据展示，以及已进入开发范围的业务接口闭环。新增产品功能默认需要同步完成数据库迁移、后端接口、共享领域模型、api-client、hooks 和 H5 使用。

## 2. 产品目标

### 2.1 业务目标

1. 建立学生、商户、家长三类用户的统一登录注册入口。
2. 为不同角色提供差异化首页模块、底部导航和快捷入口。
3. 支撑校园优选商品/服务浏览、筛选、购买确认和订单跟踪。
4. 支撑学生兼职浏览报名、商户兼职发布管理的第一阶段工作流展示。
5. 支撑学生委托/狩猎准入、上线、任务池和结算规则展示。
6. 支撑商户销售工作台、商品列表、配送/消息/售后入口展示。
7. 支撑家长商品购买和家教招募的第一阶段工作流展示。
8. 建立钱包、订单、我的、设置、资料补充等跨角色基础能力。

### 2.2 研发目标

1. H5 使用 React + TypeScript + Vite 实现。
2. 登录用户信息统一由 `client/apps/h5/src/store/global.ts` 的 `global.user` 维护。
3. 领域枚举、角色导航、接口请求结构优先复用 `client/packages/domain` 和 `client/packages/api-client`。
4. 资料补充规则统一由 `client/apps/h5/src/shared/clientPageModel.ts` 维护。
5. 产品功能默认按前后端闭环交付；除非明确为静态视觉/文案调整，不得只修改 H5 或只修改后端。
6. H5 源码使用 `@h5`、`@components`、`@pages`、`@shared`、`@store`、`@tools`、`@app-types` 全局别名，业务代码不得继续新增跨目录相对路径引用。
7. H5 共享 TypeScript 类型集中维护在 `client/apps/h5/src/types`，通过 auto-import 生成声明和 `global.d.ts` 暴露给业务代码。

## 6. 认证与注册需求

### AUTH-01 手机号验证码登录

| 项目 | 需求 |
| --- | --- |
| 入口 | 登录页默认展示“验证码登录” |
| 字段 | 手机号、验证码 |
| 校验 | 手机号通过 `validateByKey("phone", value)` 校验；验证码必须为 `000000` |
| 接口 | `POST /api/client/auth/login` |
| 成功 | 若账号存在未完成的注册后角色选择，则进入角色选择流程；否则写入登录会话并进入当前角色默认模块 |
| 失败 | 展示后端错误或本地校验错误 |

### AUTH-02 密码登录

| 项目 | 需求 |
| --- | --- |
| 入口 | 登录页可切换“密码登录” |
| 字段 | 手机号、密码 |
| 校验 | 手机号通过 `validateByKey("phone", value)` 校验；密码不少于 6 位；本地存在该手机号的密码哈希凭据；哈希匹配 |
| 当前实现 | H5 本地校验密码后，使用固定验证码调用现有登录接口换取会话；若账号存在未完成的注册后角色选择，则继续角色选择流程 |
| 安全要求 | H5 本地只保存盐值和哈希，不保存明文密码 |
| 待接入 | 后端正式密码登录接口上线后，替换本地校验方案 |

### AUTH-03 注册

| 项目 | 需求 |
| --- | --- |
| 入口 | 登录页切换“注册” |
| 字段 | 手机号、验证码、邀请码 |
| 校验 | 手机号通过 `validateByKey("phone", value)` 校验；验证码必须为 `000000` |
| 邀请码 | 选填；填写后前端随注册请求透传，当前阶段后端未接时可忽略 |
| 禁止项 | 注册表单不展示角色选择 |
| 接口 | `POST /api/client/auth/register` |
| 成功 | 生成临时注册会话，记录未完成角色选择标记，强制进入角色选择页 |
| 失败 | 展示注册失败原因 |

### AUTH-04 注册后角色选择

| 项目 | 需求 |
| --- | --- |
| 入口 | 注册成功后自动进入 |
| 可选角色 | 学生、商户、家长 |
| 规则 | 未选择角色不得进入登录后页面 |
| 再次登录 | 注册成功后未完成角色选择的账号，再次验证码登录或密码登录时仍必须继续角色选择流程 |
| 下一步 | 选择角色后进入资料补充页 |
| 返回 | 支持返回登录 |

### AUTH-05 注册后资料与密码设置

| 项目 | 需求 |
| --- | --- |
| 入口 | 注册后选择角色后进入 |
| 必填项 | 昵称、登录密码、重复密码确认 |
| 可选项 | 生日可留空；学生/商户可直接填写地址信息字段；家长默认不展示地址录入，提供“添加地址信息”和“添加孩子信息”快捷文字，点击后在表单中展开对应收集项 |
| 校验 | 昵称不能为空；密码不少于 6 位；两次密码一致；联系电话如填写必须通过 `validateByKey("contactPhone", value)` 校验 |
| 接口 | `POST /api/client/auth/select-role` |
| 成功 | 清除未完成角色选择标记；保存昵称到 H5 登录会话；保存生日、可选地址和可选孩子信息草稿；若家长展开并填完整地址则创建服务端地址；保存本地密码哈希；进入角色默认模块 |
| 返回 | 支持返回重选角色 |

### AUTH-06 忘记密码

| 项目 | 需求 |
| --- | --- |
| 入口 | 登录页“忘记密码？” |
| 字段 | 手机号、验证码、新密码、确认密码 |
| 校验 | 手机号通过 `validateByKey("phone", value)` 校验；验证码必须为 `000000`；新密码不少于 6 位且两次一致 |
| 当前短信规则 | 不接短信发送，验证码固定 `000000` |
| 成功 | 保存本地密码哈希，自动切换到密码登录 |

### AUTH-07 设置页手机号与密码安全

| 项目 | 需求 |
| --- | --- |
| 入口 | 设置页“手机号与安全”区块 |
| 变更手机号字段 | 新手机号、验证码 |
| 重置密码字段 | 手机号、验证码、新密码、确认密码 |
| 校验 | 手机号通过 `validateByKey("phone", value)` 校验；验证码必须为 `000000`；重置密码时新密码不少于 6 位且两次一致 |
| 当前实现 | 第一阶段仅更新 H5 本地 session 手机号和本地密码哈希，后端手机号/密码接口后续接入 |
| 成功反馈 | 设置页展示操作成功提示 |

## 7. 资料补充需求

### PROFILE-01 统一地址信息模板

注册后资料补充和登录后资料补充统一使用地址信息表单。字段如下：

| 字段 | 说明 | 输入规则 |
| --- | --- | --- |
| 姓名 | 收货、联系、报名或服务沟通时使用的联系人姓名 | 文本输入，注册后可留空，场景补充时必填 |
| 常用区域 | 用户常用校内或服务区域 | 支持预设区域 datalist，也允许自定义输入 |
| 楼栋楼层 | 宿舍、办公点、门店或服务点所在楼栋楼层 | 文本输入 |
| 收货地址 | 商品或服务交付的详细地址 | 文本输入 |
| 联系电话 | 当前业务联系手机号 | 电话输入，通过 `validateByKey("contactPhone", value)` 校验 |

注册后选择角色进入资料页时，昵称、登录密码和重复密码确认必须填写；昵称和生日是账户展示字段，不属于地址信息组件。生日和地址信息字段可留空；登录后由业务场景触发的资料补充弹窗必须补齐全部地址字段后才允许保存。

### PROFILE-02 地址信息组件

| 项目 | 需求 |
| --- | --- |
| 组件 | `client/apps/h5/src/components/AddressInfoForm` |
| 编辑模式 | 用于注册后资料补充和登录后资料补充弹窗，展示地址字段输入框 |
| 列表预览模式 | 用于普通地址信息展示，按字段逐行展示，未填写字段显示“未填写” |
| 卡片预览模式 | 用于设置页地址列表，紧凑展示联系人、电话、区域、楼栋楼层和收货地址 |
| 状态 tag | 卡片预览模式必须展示“当前使用”或“未使用” |
| 快捷操作 | 卡片预览模式必须提供编辑入口，非当前地址可提供“设为当前”入口 |
| 校验 | 编辑模式下字段值通过 `client/apps/h5/src/tools/validation.ts` 的 `validateByKey` 按 key 匹配校验规则 |
| 数据源 | 字段定义统一来自 `client/apps/h5/src/shared/clientPageModel.ts` 的地址信息模板 |

### PROFILE-03 资料补充交互

1. 当用户进入或操作某模块且资料缺失时，展示 `context-card` 提示。
2. `context-card` 只展示补充资料提示文案和快捷入口，不展示资料详情。
3. 点击“补充资料”打开全局资料补充弹窗。
4. 地址信息弹窗字段全部补齐后才允许保存。
5. 设置页需要以地址卡片列表展示地址信息，并支持新增、编辑和切换当前使用地址。

### FEATURED-03 订单状态

购买订单状态流为：待配送/备货中、配送中、已送达、待确认、已完成。

规则：
1. 待确认 48 小时自动完成。
2. 已完成 7*24 小时内可申请退款。
3. 订单应提供评价、申请退款、举报/投诉入口。

### TUTOR-04 试课结果与议价结算

1. 试课过程中，家长端进行中家教卡片显示“试课通过”和“试课不通过”。
2. 点击“试课不通过”时，家长确认试课费用并发起不通过流程；学生端出现“试课结果”按钮，可查看结果和结算金额。
3. 学生端不填写协商金额时，按钮为“同意”，点击后进入结算：扣除家长账号金额并入账学生钱包。
4. 学生端填写大于 0 且不等于结算金额的协商金额时，按钮变为“协商”，点击后推送给家长。
5. 家长收到协商推送后，进行中卡片显示“协商”按钮；点击打开协商列表，选择卡片查看协商内容。
6. 任一方同意协商金额后结束试课并结算；不同意时可继续输入金额推送给对方，直至一方同意。
7. 试课不通过只结算试课家教的费用和学生端试课任务，家长端家教招募仍保持进行中。
8. 点击“试课通过”时，家长输入试课金额、家教每日金额、选择孩子并打开家教日程编辑器；确认后推送给学生。
9. 学生可接受或拒绝家教日程；拒绝则结算试课费用并结束学生端进行中家教，接受则兼职变为正式进行中。
10. 正式家教进行中时，家长可变更课程安排，但必须经学生同意。
11. 家教全部结束后，任一方可发起结束家教，另一方同意后结算金额；结束的家教进入订单列表兼职分类。
12. 试课结果和正式家教阶段仍仅完成 H5 交互框架；钱包扣款、入账、协商推送、家教日程审批和正式家教结算订单沉淀需要后端接口补齐。

| 未填写字段 | 展示“未填写” |
| 设置项 | 平台协议、版本&更新 |

接口统一使用：

```json
{
  "code": "OK",
  "message": "success",
  "data": {}
}
```

H5 请求层需要：
1. 默认从 `http://127.0.0.1:8080` 请求后端。
2. 支持通过 `globalThis.__UNKNOWN_API_BASE_URL__` 覆盖后端地址。
3. 自动携带本地登录 token。
4. 接口失败时展示真实错误，不使用本地假数据兜底。

## 18. 数据与状态规则

### 18.1 本地存储

| Key | 内容 | 说明 |
| --- | --- | --- |
| `unknown.client.auth.session` | 登录会话 | `accessToken`、`refreshToken`、角色、手机号等 |
| `unknown_client_profile_completion_v1` | 临时资料草稿 | 仅用于注册/补充资料输入过程的本地草稿；登录后的地址准入以服务端地址接口为准 |
| `unknown_client_password_credentials_v1` | H5 本地密码凭据 | 盐值、密码哈希、更新时间；不保存明文 |
| `unknown_client_pending_registration_v1` | 未完成注册角色选择标记 | 以原始手机号为 key，注册成功后写入，角色确认成功后清除 |

补充规则：登录后的地址列表、当前地址、首页资料补充提示、购买/兼职/委托/家教前置地址校验，必须以 `GET /api/client/profile/addresses` 返回的当前地址为准；本地资料草稿不得作为已补齐地址的判断依据。注册后资料补充若五个地址字段全部填写，角色确认后立即调用 `POST /api/client/profile/addresses` 创建当前地址；若跳过或字段不完整，后续由首页资料提示卡和设置页继续引导补充。

### 18.2 全局用户状态

登录成功后，H5 必须将用户信息写入 `global.user`，登录后页面读取全局 store，不重复传递登录用户对象。

### 18.3 路由规则

1. 未登录访问任意页面跳转 `/login`。
2. 登录后访问 `/` 或 `/login`，跳转到当前角色默认主模块。
3. 主模块路由驱动底部导航激活状态。
4. 我的与设置是独立路由，钱包与订单是 App 内栈式次级页面。

## 20. 验收标准

### 20.1 通用验收

1. 未登录用户只能访问登录页。
2. 登录后根据角色进入正确默认模块。
3. 底部导航与角色模块一致。
4. 悬浮头像能通过简单账户卡展示昵称、账户状态、角色、信用值和已通过的家教/狩猎标签，信用值位于账号卡标题区说明文案内，不再展示状态/角色子卡片，卡片头上下居中且标题区高度与 40px 图标一致，标题区 p 元素使用 12px 淡灰色，并在账号卡片内提供红色退出入口；家教认证通过后账号卡内展示家教开关，家教开关子卡片文字不使用粗体；通过简单钱包卡展示总金额、状态值、可提现金额和与可提现同级的居中充值容器；待认证、认证中或冻结状态才展示家教/狩猎认证卡；家教申请通过后快捷入口展示课程日历，快捷入口支持换行展示；学生包含发布、回收、消息、建议/投诉和更多，发布入口绿色加粗，回收入口蓝色加粗；家长不展示家教认证入口，发布入口只允许家教发布，家教快捷入口文案为“家教日程”；订单模块卡迁移到我的页面展示。
5. 资料缺失时，仅展示提示和补充入口，不展示资料详情。
6. 设置页展示独立昵称区块、手机号安全区块、学生家教卡片更多入口和地址列表，支持修改昵称、变更手机号、重置密码、查看资格申请信息、编辑家教学科、新增地址、编辑地址和切换当前使用地址。
7. 发布委托或回收成功后，后端 `hunting_task` 产生真实记录，workspace 任务池接口可读到该记录，H5 委托列表即时展示。

### 20.2 登录注册验收

1. 验证码登录必须校验手机号和 `000000`。
2. 密码登录可切换，未设置密码时给出提示。
3. 注册页不出现角色选择。
4. 注册页邀请码为选填，未填写也可提交注册。
5. 注册成功后必须选择角色。
6. 注册成功后未选择角色即返回登录，再次登录时仍必须进入角色选择流程。
7. 选择角色后必须填写昵称、设置登录密码和重复密码。
8. 注册后昵称和生日不进入地址模块；生日和地址信息可留空进入。
9. 忘记密码使用 `000000` 校验并重置本地密码哈希。

### 20.3 模块验收

1. 优选列表能按筛选项展示商品，家长端只展示快递商品。
2. 购买前缺少优选资料时，必须提示补充资料。
3. 购买确认能展示配送方式、支付方式和金额拆分。
4. 兼职学生侧能展示列表、筛选、报名入口和状态流。
5. 商户兼职能展示工作台、快捷入口和职位操作。
6. 委托/狩猎上线前必须检查地址信息。
7. 商户商品工作台能展示指标、快捷入口和商品操作。
8. 家教模块能展示需求、申请人和招募操作。
9. 钱包能展示月度汇总、月份选择和账单列表。
10. 订单能展示订单、风险样式和操作入口。

## 21. 详细页面与交互说明

本章节用于补充研发落地需要的页面级说明。每个页面至少包含页面目标、进入方式、展示内容、用户操作、校验规则、状态反馈和异常处理。后续新增或调整功能时，不允许只改需求清单，必须同步维护对应页面交互说明。

### 21.1 登录页

页面目标：完成未登录用户的身份进入、账号注册、密码登录、忘记密码和注册后强制角色选择链路。

进入方式：
1. 未登录访问任意页面时自动跳转 `/login`。
2. 用户主动退出登录后回到 `/login`。
3. 注册后点击“返回登录”回到登录表单，但未完成角色选择标记需要保留。

页面结构：
1. 顶部说明卡：展示“佚名客户端”、当前支持的登录方式、本地验证码。
2. 登录/注册 Tab：同一卡片内切换“登录”和“注册”。
3. 登录方式 Tab：仅登录模式展示，支持“验证码登录”和“密码登录”。
4. 手机号输入框：所有模式均展示。
5. 验证码输入框：验证码登录和注册模式展示。
6. 密码输入框：密码登录模式展示。
7. 忘记密码入口：登录模式展示。
8. 主按钮：根据状态显示“验证码登录”“密码登录”“注册”“登录中”“注册中”。

验证码登录交互：
1. 用户输入手机号。
2. 用户输入验证码，或点击“填入”自动填入 `000000`。
3. 点击“验证码登录”后，先通过 `validateByKey("phone", value)` 校验手机号，再校验验证码。
4. 校验通过后调用 `POST /api/client/auth/login`。
5. 登录成功后若该手机号存在未完成角色选择标记，则进入角色选择页。
6. 无未完成标记时写入 `global.user`，并跳转当前角色默认模块。
7. 接口失败时展示后端错误文案；本地校验失败时展示本地提示。

密码登录交互：
1. 用户切换到“密码登录”。
2. 用户输入手机号和密码。
3. 点击“密码登录”后，先通过 `validateByKey("phone", value)` 校验手机号，再校验密码长度。
4. H5 查询本地密码凭据；若没有凭据，提示“该手机号还未设置密码，请先使用验证码登录或注册后设置密码。”
5. 本地哈希校验失败时提示“登录密码不正确。”
6. 本地哈希校验通过后，第一阶段使用固定验证码调用现有登录接口换取会话。
7. 若该手机号存在未完成角色选择标记，则进入角色选择页。
8. 后端正式密码接口上线后，此步骤必须调整为服务端密码校验。

注册交互：
1. 用户切换到“注册”。
2. 页面隐藏登录方式 Tab，仅展示手机号和验证码。
3. 注册表单不得展示角色选择。
4. 点击“注册”后通过 `validateByKey("phone", value)` 校验手机号，并校验验证码为 `000000`。
5. 调用 `POST /api/client/auth/register`。
6. 注册成功后记录该手机号的未完成角色选择标记。
7. 注册成功后进入角色选择页，不允许直接进入业务页面。

忘记密码交互：
1. 用户点击“忘记密码？”进入重置密码卡片。
2. 输入手机号、验证码、新密码、确认密码。
3. 手机号通过 `validateByKey("phone", value)` 校验。
4. 验证码固定 `000000`；短信发送暂不接入。
5. 新密码不少于 6 位，确认密码必须一致。
6. 校验通过后保存本地盐值哈希，切换到密码登录，并回填手机号和密码。
7. 保存失败时提示“密码保存失败，请稍后重试。”

异常与边界：
1. 手机号为空或格式错误时，不发起接口请求。
2. 验证码不是 `000000` 时，不发起接口请求。
3. 密码登录不保存明文密码。
4. 浏览器不支持 `crypto.subtle` 时，提示改用验证码登录。
5. 登录成功后不保留登录页局部错误提示。

### 21.2 注册后角色选择页

页面目标：让新注册用户在进入系统前确认唯一客户端角色。

进入方式：注册接口成功后自动进入。

展示内容：
1. 标题：选择角色。
2. 描述：注册已完成，选择角色后才能进入客户端。
3. 角色卡片：学生、商户、家长。
4. 每个角色展示角色名称和角色说明。
5. 底部提示：角色选择为必选步骤；昵称和密码必须设置后才能进入，地址信息可以留空。
6. 返回登录按钮。

交互规则：
1. 点击角色卡片后，进入注册后资料与密码设置页。
2. 未选择角色时，不允许进入登录后页面。
3. 点击返回登录，需要清空页面内临时注册流程状态，包括已选角色、资料草稿和提交中状态。
4. 点击返回登录不得清除未完成角色选择标记；该手机号再次登录时仍必须回到角色选择页。
5. 提交中状态下角色卡片和返回按钮禁用。

异常与边界：
1. 临时注册会话丢失时，应回到登录页重新注册或登录。
2. 角色列表应与 `roles` 配置一致，不在页面内写死额外角色。

### 21.3 注册后资料与密码设置页

页面目标：在确认角色后，收集必填昵称和登录密码，并允许用户补充生日与地址信息。

进入方式：注册后选择角色进入。

展示内容：
1. 标题展示“补充地址信息”。
2. 角色说明和地址资料说明。
3. 昵称输入框：必填，独立于地址信息组件，用于登录后的头像弹窗、我的页和设置页展示。
4. 生日输入框：选填，独立于地址信息组件，用于账户默认卡片展示。
5. 地址信息字段：姓名、常用区域、楼栋楼层、收货地址、联系电话。
6. 必填字段：昵称、登录密码、重复密码。
7. 操作按钮：返回重选角色、填写昵称并进入/设置密码并进入/留空资料并进入/确认并进入。
8. 底部说明：昵称和登录密码为必填；生日和地址字段可以先留空，后续可在设置页维护地址列表。

交互规则：
1. 昵称为空时，不允许进入并展示必填提示。
2. 登录密码少于 6 位时，点击进入展示警告。
3. 重复密码为空或两次不一致时，点击进入展示警告。
4. 生日为空时允许进入；填写后保存到本地资料草稿的 `birthday` 字段。
5. 地址信息字段为空时允许进入，但按钮文案显示“留空资料并进入”。
6. 联系电话如填写，必须通过 `validateByKey("contactPhone", value)` 校验。
7. 资料字段保存前需要去除首尾空格；空字符串不得作为已填写资料保存。
8. 点击返回重选角色时，清空当前角色、昵称、生日、密码输入和地址草稿，返回角色选择页。
9. 点击确认进入时，先调用 `POST /api/client/auth/select-role` 确认角色。
10. 角色确认成功后清除未完成角色选择标记，保存昵称到 H5 登录会话，保存生日、地址信息草稿和本地密码哈希，再进入角色默认模块。

异常与边界：
1. 角色确认接口失败时，不保存密码凭据，提示“角色确认或密码保存失败，请稍后重试。”
2. 本地密码保存失败时，不进入业务页面。
3. 资料字段使用 datalist 时，允许选择预设区域，也允许自定义输入。

### 21.4 全局页面壳

页面目标：为所有登录后页面提供统一导航、状态、快捷入口、资料补充和工作流弹窗。

页面组成：
1. 主页面不展示独立 top-bar 卡片；当前模块由底部导航高亮和模块标题区表达。
2. 主内容区：根据路由渲染当前模块。
3. 资料提示卡：当前模块资料缺失时展示。
4. 右下角悬浮头像：进入我的快捷入口。
5. 订单快捷按钮：存在当前角色订单时展示。
6. 底部导航：展示当前角色主模块。
7. 全局弹窗：购买确认、资料补充、进行中订单列表、家教认证信息、家教课程日历。

路由交互：
1. 未登录访问任何页面，强制进入 `/login`。
2. 已登录访问 `/` 或 `/login`，跳转当前角色默认主模块。
3. 点击底部导航时，关闭我的浮层、进行中订单弹层、资料弹窗和家教相关弹窗。
4. 点击我的或设置独立路由时，清空内部页面栈。
5. 钱包和订单作为 App 内栈式页面展示时，顶部有返回按钮。

数据交互：
1. 登录后根据角色请求 `GET /api/client/home?role={role}`。
2. 登录后根据角色请求 `GET /api/client/workspace?role={role}`。
3. home profile 返回后同步到全局 `global.user`。
4. workspace orders 需要按当前角色过滤。
5. 数据加载中时，页面应展示加载态文案。
6. 数据异常时，页面应展示错误提示，不使用本地假数据兜底。

### 21.5 资料提示卡与资料补充弹窗

资料提示卡：
1. 展示条件：当前模块存在缺失的地址信息。
2. 展示文案：补充资料后继续使用。
3. 不展示具体字段值，不展示资料详情。
4. 只提供“补充资料”快捷入口。

资料补充弹窗：
1. 由资料提示卡、购买前校验、狩猎上线前校验触发。
2. 顶部展示地址信息模板标题和说明。
3. 使用 `AddressInfoForm` 编辑模式展示姓名、常用区域、楼栋楼层、收货地址、联系电话。
4. 常用区域字段使用 datalist 提供校内区域预设，也允许自定义输入。
5. 字段为空时使用缺失样式；联系电话格式错误时展示字段级错误提示。
6. 全部字段补齐且联系电话通过 `validateByKey("contactPhone", value)` 校验后才能点击“保存资料”。
7. 保存成功后关闭弹窗，更新本地资料草稿和全局用户资料。
8. 点击取消或关闭图标时，不保存当前输入。

异常与边界：
1. 浏览器本地存储不可用时，保存失败并提示。
2. 保存后应立即影响当前模块资料缺失状态。
3. 设置页地址列表承担新增和编辑能力；业务场景资料补充仍通过全局资料补充弹窗完成。

### 21.6 优选/商品页

页面目标：为学生和家长展示可购买商品/服务，并完成购买确认前置流程。

进入方式：
1. 学生底部导航点击“优选”。
2. 家长底部导航点击“优选”。
3. 登录后角色默认模块可能直接进入该页。

展示内容：
1. 标题：学生展示“优选商品/服务”，家长展示“快递商品”。
2. 副标题：学生说明自营耗材、平台闲置、商户商品与服务；家长说明固定快递配送。
3. 商品数量：加载中时展示“加载中”，加载后展示数量。
4. 筛选项：自营、现货、小时达、最新发布。
5. 商品卡片：品类图标、标题、描述、来源、默认配送方式、库存、位置、零售价、价格、合计。
6. 商品操作：收藏、举报、购买/预约或快递购买。
7. 购买状态流说明卡。

筛选交互：
1. 点击筛选项更新当前列表。
2. 自营筛选展示来源包含平台自营的商品。
3. 现货筛选展示库存大于 0 的商品。
4. 小时达筛选展示支持立刻配送的商品。
5. 最新发布当前按接口顺序展示。
6. 家长角色在任何筛选下都只展示支持快递配送的商品。

购买交互：
1. 点击购买按钮前，校验当前角色地址信息。
2. 资料缺失时提示“请先补充 xxx”，并打开资料补充弹窗。
3. 资料完整时打开购买确认弹窗。
4. 商户角色不可购买，购买按钮禁用。
5. 购买提交中，按钮展示提交中或禁用态，避免重复提交。

购买确认弹窗：
1. 展示商品标题和“购买确认”说明。
2. 展示配送方式：学生按商品支持方式展示，家长只展示快递配送。
3. 展示付款方式：微信、支付宝、余额。
4. 展示金额拆分：商品、服务费、履约费、合计。
5. 点击提交支付调用 `POST /api/client/products/purchase`。
6. 成功后提示订单号、订单状态和应付金额，关闭弹窗并进入订单详情。
7. 失败时展示接口错误。

### 21.8 委托/狩猎页

页面目标：聚焦委托任务列表检索、区域筛选、排序和任务操作，规则信息通过顶部滚动字幕轻量提示。

进入方式：学生底部主导航点击“委托”，或双击悬浮“我的”展开狩猎快捷按钮后进入，也可从头像弹窗点击“发布”。

页面结构：
1. 顶部单行滚动字幕展示结算规则和取消协商规则。
2. 搜索输入框、区域筛选图标、排序图标和狩猎模式图标同一行展示。
3. 点击区域筛选图标展开区域选项，区域基于委托目的地自动提取，支持“全部区域”。
4. 点击排序图标展开默认排序、时间优先、金额从高到低、金额从低到高。
5. 任务池卡片列表是页面主内容，仅展示状态为“发布”或“报价”的委托，不展示履约中、完成、取消或异常委托；不展示全局资料提示卡、狩猎准入卡、发布说明卡、结算规则卡和上线/下线按钮。
6. 狩猎模式开启时每 3 秒动态刷新任务池，未开启时展示手动刷新入口。
7. 任务池列表在剩余页面高度内独立滚动，滚动视窗需要保留左右边距，避免卡片贴边或撑高整页。

滚动字幕组件：
1. 组件路径：`client/apps/h5/src/components/ScrollingTicker`。
2. 默认方向为横向滚动。
3. 默认速度为 3000ms。
4. 支持通过属性调整滚动方向和滚动速度。

任务卡片交互：
1. 卡片展示标题、发布时间、发布者名称、发布者脱敏手机号、委托目的地、委托金额、押金金额和要求；手机号中间 4 位使用 `****` 脱敏；委托金额使用大一号红色突出显示；不展示模式、紧急程度、描述、结算规则和取消协商规则。
2. 当前账号发布的委托卡片展示“我的”角标，不展示联系、报价、接受委托、查看报价和报价数量角标；详情弹窗也不展示服务方操作按钮。
3. 点击卡片非按钮区域打开委托详情弹窗，弹窗以委托表单预览模式展示标题、发布时间、发布者名称、发布者脱敏手机号、委托目的地、委托金额、押金金额、描述和要求。
4. 非本人发布的详情弹窗内保留“联系”和主操作快捷按钮；协商金额任务按钮文案展示“报价”，固定金额任务按钮文案展示“接受委托”；自己的委托不展示联系、报价或接受按钮。
5. 固定金额委托点击“接受委托”后调用后端接受接口，成功后进入“履约中”，并从委托任务池列表移入进行中弹窗。
6. 协商金额委托点击“报价”后打开报价金额弹窗，服务方提交后任务保持“报价”；发布方只能从进行中弹窗点击“查看报价”打开报价列表，列表展示报价名称、报价金额、报价时间，单选报价并确认后委托状态变为“履约中”。
7. 发布委托默认不需要押金；选择需要押金后必须输入押金金额；接受固定金额委托或确认协商报价时，系统冻结服务方钱包对应押金，余额不足时操作失败并展示消息提示。
8. 未完成狩猎认证时点击“联系”“接受委托”“报价”不执行原操作。
9. 待认证或冻结状态打开认证提示弹窗，弹窗展示当前认证状态、提示信息和“去认证”按钮，点击后进入狩猎认证页面。
10. 认证中状态不打开弹窗，仅展示消息提示“狩猎认证系统审批中...”。

2. 页面标题为“狩猎认证”，作为我的模块的次级页面展示，点击返回回到进入前页面。
3. 表单字段包括姓名、性别、年龄、籍贯、身份证、学校、专业。
4. 全部字段均为必填。
5. 年龄必须为 1 到 100 之间的整数；身份证必须符合 18 位身份证格式。
6. 点击“提交认证”前必须完成全部必填字段校验。
7. 点击“提交认证”调用 `POST /api/client/profile/hunting-certification`，服务端将 `app_user.hunting_certification_status` 更新为 `reviewing`。
8. 提交成功后自动返回当前主模块首页，并展示“狩猎认证已提交，当前状态为认证中。”全局提示，同时刷新首页资料同步服务端认证状态。
9. 认证中状态下，头像弹窗只展示“认证中”状态卡；待认证时展示入口，认证通过且状态为正常时不展示卡片，仅在账户卡昵称后展示“狩猎”标签。
10. 狩猎认证状态来自数据库字段 `app_user.hunting_certification_status`，枚举为待认证、认证中、正常、冻结；其中 `normal` 表示认证通过。

交互规则：
1. 点击返回回到上一层。
2. 点击设置按钮进入 `/settings`。
3. 点击钱包详情进入钱包次级页面。
4. 交易和记录按钮当前为入口展示，后续接入对应页面。
5. 进行中事项不在我的页面内展示列表卡片，统一通过悬浮进行中快捷按钮进入订单弹窗。

### 21.15 设置页

页面目标：展示独立昵称、手机号与安全、学生家教资格信息、地址列表、地址新增/编辑入口和基础设置项；原账户信息模块不再展示。

进入方式：
1. 我的页面设置按钮。
2. 家长悬浮头像“孩子”快捷入口。
3. 路由 `/settings`。

展示内容：
1. 昵称：独立区块展示当前昵称和“修改昵称”快捷入口。
2. 手机号与安全：独立展示当前手机号，并提供“变更手机号”和“重置密码”快捷入口。
3. 家教卡片更多：学生角色展示资格申请信息入口，入口展示当前资格状态。
4. 地址信息：以列表展示所有本地地址卡片。
5. 地址卡片：使用 `AddressInfoForm` 卡片预览模式紧凑展示姓名、联系电话、常用区域、楼栋楼层和收货地址。
6. 当前使用状态：每张地址卡必须展示“当前使用”或“未使用”状态 tag。
7. 快捷入口：地址卡提供编辑按钮；非当前地址提供“设为当前”按钮。
8. 新增地址入口：地址列表底部展示“新增地址”快捷入口。
9. 设置项：平台协议、版本&更新。
10. 不展示项：不展示原账户信息模块中的角色、账号状态、信用值聚合卡。

交互规则：
1. 从“我的”进入设置页时，点击返回必须回到“我的”页面。
2. 从其他入口进入设置页时，点击返回回到当前角色主模块。
3. 点击“修改昵称”打开昵称修改弹窗。
4. 点击“变更手机号”打开手机号变更弹窗。
5. 点击“重置密码”打开重置密码弹窗。
6. 点击“家教卡片更多”打开资格申请信息弹窗；弹窗内学科可编辑，其他认证资料只读。
7. 点击“新增地址”打开新增地址弹窗。
8. 点击地址卡“编辑”打开编辑地址弹窗，并回填该地址数据。
9. 点击“设为当前”后，该地址标记为当前使用，并同步到全局资料草稿。
10. 新增地址保存成功后默认成为当前使用地址。
11. 设置项当前为入口展示，后续接对应编辑页或协议页。
12. 地址信息完成度按当前使用地址字段计算。

修改昵称弹窗：
1. 字段：昵称。
2. 昵称为必填，空值时禁用保存并展示字段级提示。
3. 点击保存后更新 H5 本地 session 的 `displayName`，同步 `global.user.displayName` 和 `global.user.profileName`。
4. 保存成功后关闭弹窗，设置页昵称区块展示成功提示。
5. 点击取消、关闭图标或遮罩时，不保存当前输入。

变更手机号弹窗：
1. 字段：新手机号、验证码。
2. 新手机号必须通过 `validateByKey("phone", value)` 校验。
3. 验证码固定为 `000000`；短信发送暂不接入。
4. 校验通过后更新 H5 本地 session 中的手机号。

重置密码弹窗：
1. 字段：手机号、验证码、新密码、确认密码。
2. 手机号必须通过 `validateByKey("phone", value)` 校验。
3. 验证码固定为 `000000`；短信发送暂不接入。
4. 新密码不少于 6 位，确认密码必须一致。
5. 校验通过后保存本地盐值哈希，不保存明文密码。

新增/编辑地址弹窗：
1. 使用 `AddressInfoForm` 编辑模式展示姓名、常用区域、楼栋楼层、收货地址、联系电话。
2. 五个地址字段均必填。
3. 联系电话必须通过 `validateByKey("contactPhone", value)` 校验。
4. 表单未补齐或校验不通过时，“保存地址”按钮禁用。
5. 点击取消、关闭图标或遮罩时，不保存当前输入。

异常与边界：
1. 用户资料为空且无地址列表时，展示“暂无地址”空状态和新增地址入口。
2. 不同角色均展示同一套地址信息字段。
3. 当前阶段昵称、地址簿、手机号变更和密码重置均存储在 H5 本地，后续接入后端接口后需要迁移。
4. 登录用户信息必须从 `global.user` 读取。

地址接口闭环补充规则：
1. 设置页地址列表必须通过 `GET /api/client/profile/addresses` 读取服务端地址，不使用本地地址簿兜底。
2. 地址卡片提供编辑、删除按钮；非当前地址提供“设为当前”按钮。
3. 新增地址调用 `POST /api/client/profile/addresses`，成功后默认成为当前使用地址。
4. 编辑地址调用 `PUT /api/client/profile/addresses/{addressId}`；当前地址编辑成功后同步全局资料草稿。
5. 设为当前调用 `POST /api/client/profile/addresses/{addressId}/current`，成功后按返回列表刷新。
6. 删除地址调用 `DELETE /api/client/profile/addresses/{addressId}`；删除当前地址后服务端自动选择最近维护的地址为当前地址。
7. 首页资料提示、购买/兼职/委托/家教前置地址校验，必须使用地址接口返回的当前地址判断，不得读取本地草稿判断为已补齐。
8. 地址接口失败、保存失败、切换失败或删除失败时，通过全局 Toast 展示真实错误。

### 21.16 全局 Toast 与错误反馈

Toast 目标：用统一方式反馈成功、警告和错误。

触发场景：
1. 登录成功、注册成功、资料保存成功、购买成功。
2. 手机号格式错误、验证码错误、密码错误、资料缺失。
3. 接口失败、密码保存失败、浏览器存储不可用。

交互规则：
1. Toast 需要展示标题和说明。
2. 用户可点击关闭。
3. 页面切换、返回或打开新流程时，应清理不再适用的 Toast。
4. 同一时间只展示当前最重要的一条反馈。

### 21.17 加载、空态与失败态

加载态：
1. 首页和工作台数据请求中，页面展示“加载中”。
2. 商品列表请求中，商品数量展示“加载中”。
3. 提交购买、登录、注册、角色确认时，按钮进入禁用或提交中文案。

空态：
1. 营销页当前是明确预留空态。
2. 后续模块如果列表为空，需要展示空态文案和下一步入口。

失败态：
1. 后端接口失败展示真实错误。
2. 不允许用本地假数据兜底掩盖接口错误。
3. 资料保存失败提示检查浏览器存储权限。
4. 密码能力不支持时提示改用验证码登录。

### 21.20 优选/兼职列表工具条与地址提示补充

1. 优选/商品页参考委托页列表结构，标题区下方展示搜索输入框、筛选图标和排序图标；页面外层固定视口高度，工具条不随商品列表滚动。
2. 优选筛选项为自营、现货、小时达、最新发布；排序项为默认排序、价格从低到高、价格从高到低、库存优先。
3. 兼职学生侧参考委托页列表结构，标题区下方展示搜索输入框、地点筛选图标和排序图标；页面外层固定视口高度，工具条不随兼职列表滚动。
4. 兼职地点筛选项从兼职列表地点字段中提取；排序项为最新发布和时薪优先。
5. 优选和兼职列表筛选后为空时，必须展示空状态文案，不展示空白列表。
6. 登录后首页资料提示卡必须以地址接口返回的当前地址判断。地址列表为空、没有当前地址或当前地址字段不完整时，优选、兼职、委托/狩猎等主模块均展示补充资料入口。
7. 地址接口返回前使用稳定空列表作为前端派生数据输入，禁止使用每次渲染重新创建的默认数组触发状态同步循环。
8. 优选和兼职的列表容器必须使用 `minmax(0, 1fr)` 撑满剩余区域，并在容器内部滚动；状态说明卡放入列表滚动容器内。
9. 主页面移除 top-bar 卡片后，优选、兼职和委托列表高度需要重新按无顶部栏布局计算，避免列表底部留空或被底部导航遮挡。

### 21.21 H5 组件边界与样式归属规范

1. 共享组件按 `client/apps/h5/src/components/<Component>/index.tsx` 和同目录 `index.less` 维护；组件专属样式不得继续新增到 `styles.less`。
2. 页面私有组件继续维护在 `pages/<Module>/components/*.tsx`，样式归入对应页面 `index.less`。
3. `AddressInfoForm` 编辑模式默认启用，调用方不需要传 `mode="edit"`；组件内部维护输入草稿，向父级回传完整 draft 和变更字段 key。
4. `AddressInfoForm` 卡片预览模式支持传入地址条目 item，组件内部绑定“设为当前、编辑、删除”按钮并调用 `onUse(item)`、`onEdit(item)`、`onDelete(item)`。
5. 纯提示类交互应收敛在组件或页面内部，例如进行中弹窗的消息/电话提示、委托页对自己发布委托的阻断提示，不再由 `App.tsx` 透传仅展示 toast 的回调。
6. 删除或拆分组件目录前，必须检查显式 import、JSX 使用、`auto-imports.d.ts` 和 auto-import 配置；被自动导入暴露的组件即使没有显式 import，也不能直接删除。
7. `AppShell` 当前仍承载 `PageShell`、`ProfileContextCard`、`MinePopover`、`BottomTabs` 等运行中组件；若后续清理，应先拆分为独立组件目录并同步调整样式和 auto-import 声明。
