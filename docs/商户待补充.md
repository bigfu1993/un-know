## 4. 建议补充顺序

1. 商品/服务发布：继续补服务发布字段、商品编辑后的审核规则、预约/履约和售后规则。
2. 商户订单与履约：继续补自提、预约服务履约、改约协商细则和售后衔接。
3. 商户商品订单模块：继续补异常提醒和经营概览。
4. 商户兼职发布管理：把报名筛选、签到、聘用、完成确认和评价举报落到页面。
5. 商户售后处理：补商家自行售后的端内处理流程和平台投诉复核衔接。
6. 商户资金与结算：补商品/服务收入、兼职预付、退款扣回、提现和冻结金额。
7. 商户消息、信用与处罚：补强提醒、超时提醒、违规记录、保证金或限制策略。
8. 数据看板、多门店增强、员工子账号增强、营销工具放到后续版本。

## 5. 状态同步规则

- 每次正式补充商户端内容到 `client-plan.md` 后，需要回到本文档把对应模块状态从“待补充”改为“部分完成”或“已完成”，并在“当前说明”中写清已经补了什么。
- 每次正式补充管理端商户承接能力到 `admin-plan.md` 后，也需要同步更新本文档对应模块。
- 如果只补了入口、字段或方向，但还缺完整页面流程、状态流转或异常处理，状态保持“部分完成”。
- 如果已经补齐用户端入口、核心字段、页面动作、状态流转、管理端承接和数据对象，可改为“已完成”。
- 新增商户端需求时，先写入本文档，再决定是否进入用户端计划、管理端计划或后续版本。

商户注册与认证规则、商品订单模块首屏第一部分、全部门店汇总和门店筛选、销售/配送/消息二级页、商品卡片快捷操作、添加产品弹窗、员工子账号入口、兼职主页面、订单/配送调整诉求按钮已写入正式文档。下一步建议继续补服务发布字段、商品编辑后的审核规则、自提/预约服务履约、改约协商细则、兼职签到聘用闭环和售后处理，让商户端从“可看数据、可改商品、可处理诉求”继续走向“可完整经营”。
