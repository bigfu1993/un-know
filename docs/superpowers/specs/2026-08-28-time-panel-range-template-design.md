# TimePanel 滑动排期与用户时间模板设计

## 目标

- 将 `TimePanel` 的起止时间输入框改为双滑块范围条，时间精度为 10 分钟。
- 上午范围为 `08:00-12:00`，下午范围为 `12:00-18:00`，晚上范围为 `18:00-22:00`。
- 每个用户维护一份不包含日期的通用时间模板，可将当前日期安排记为模板，也可用模板覆盖当前日期安排。
- 从 `CalendarTime` 移除学生可用日期、可用时段和可用时间对排期编辑器的限制。

## 非目标

- 本阶段不重构日程冲突、正式雇佣、状态迁移等后续工作流。
- 本阶段不删除 `tutor_applicant.availability`、已有 workflow action 或历史数据兼容逻辑；业务推进到对应链路后再单独调整。
- 不支持多模板、模板名称、模板共享和历史版本。
- 不修改 `frontend/apps/h5/src/components/ScheduleCalendar/TimePanel/index copy.tsx`。

## 数据设计

通过新的 Flyway 迁移在 `app_user` 增加一对一模板字段：

```sql
schedule_time_template JSONB NOT NULL DEFAULT '{}'::jsonb
```

模板只保存已设置的时段，不保存日期：

```json
{
  "morning": { "start": "08:30", "end": "11:20" },
  "evening": { "start": "19:00", "end": "21:30" }
}
```

服务端校验规则：

- 只允许 `morning`、`afternoon`、`evening` 三个键。
- 时间使用 `HH:mm`，分钟必须落在 10 分钟刻度。
- 起止时间必须处于对应时段边界内，结束时间至少比开始时间晚 10 分钟。
- 空对象表示当前用户还没有模板；不接受只有开始或只有结束的不完整时段。

## 接口与全局用户状态

- `RoleProfile` 增加 `scheduleTimeTemplate`，首页用户资料加载后由 `GlobalProvider` 统一持有。
- 新增 `PUT /client/profile/schedule-time-template`，请求和响应都使用同一份结构化模板契约。
- API Client 增加更新方法；保存成功后通过 `GlobalProvider` 的受控 action 更新内存状态。
- `TimePanel` 只负责渲染滑块和触发操作；`CalendarTime` 负责读取全局模板、调用保存接口、应用模板和展示反馈。

## TimePanel 交互

每个时段渲染一条双滑块范围条：

- 未安排时，开始和结束滑块都位于该时段起点。
- 拖动产生至少 10 分钟间隔后，才写入当前日期日程并将该时段标记为已安排。
- 两个滑块重新重合时，清空该时段并回到时段起点。
- 滑块旁实时显示格式化后的起止时间。
- 时段名称仅作展示，不再点击选中或取消选中。
- 保留单时段“清空”。

顶部固定展示三个操作：

- `取消全选`：清空当前日期全部安排；无安排或过去日期时禁用。
- `记为模板`：将当前日期已安排的时间段覆盖保存到用户表；无安排、过去日期或正在保存时禁用。
- `使用模板`：使用服务端模板整组覆盖当前日期手动安排；无模板、过去日期、达到新增日期上限或存在占用冲突时禁用或拒绝并提示，不做部分覆盖。

过去日期只允许查看，全部滑块、单时段清空和顶部三个操作均不可用。

## 排期状态改造

- `TimePanel` 将逐字段回调改为原子化的 `onChangePeriodRange(periodKey, start, end)`，避免两个滑块更新产生不完整中间状态。
- `useTrialSchedule` 只有在 `end > start` 且间隔不少于 10 分钟时才把时段写为 `enabled`。
- 使用模板时一次性替换当前日期的三个时段；模板未包含的时段同步清空。
- 移除时段按钮预设、顶部全选、日期单击/双击自动生成全天安排的入口；日历日期交互只切换当前查看日期。
- 已有日程占用和最多安排天数继续生效；模板命中任一占用时段时整次拒绝。
- 删除 `availableScheduleSummary` Prop、解析状态、可选日期集合、可用时段判断、可用日程合并和调用方传参。

## 样式与可访问性

- 使用两个原生 `input[type="range"]` 叠加实现双滑块，不新增第三方依赖。
- 两个滑块分别提供明确的开始时间和结束时间 `aria-label`，实时值通过可读文本展示。
- 轨道填充区表现当前时间范围，禁用态、已安排态和不可用态延续现有 H5 色彩变量。
- 控件保持紧凑，在窄屏下不产生水平溢出或文本遮挡。
