## 4. 待确认问题

以下问题来自 `client-plan.md` 的开放项，已剔除已落地的基础架构，只保留会影响后续规则设计的事项：

- Q-01：商户发布商品的交易责任边界：平台代售、商户自售，还是平台审核后展示并由商户履约？
- Q-02：自营耗材是否进入普通商品流，还是在优选中设置独立高频入口？
- Q-03：校园服务需求是否全部进入狩猎池，高风险场景是否先进入平台人工对接？
- Q-04：狩猎实时推送第一版是否只推送审核通过的任务，报价有效期和报价超时失效规则如何设计？
- Q-05：狩猎时间是否允许跨天，还是第一版最长只到次日 0 点？
- Q-06：狩猎押金是否可退，退还需要满足哪些条件？
- Q-07：身份证和学籍信息验证第一版采用人工审核还是第三方实名/学籍验证？
- Q-08：兼职押金是否复用狩猎押金，商户发布方是否需要岗位保证金？
- Q-09：兼职结算日期是固定规则、完成后 N 天，还是发布方自定义但受平台限制？
- Q-10：项目结束后一周自动确认是否为全平台默认规则，是否按岗位类型配置？
- Q-11：人员要求中的“限性别”是否需要平台审核理由。
- Q-12：商品购买第一版支持哪些付款方式：微信、支付宝、余额、线下确认或组合支付？
- Q-13：商品购买取消、退款、改配送时间和联系电话变更的自助范围是什么？
- Q-14：兼职收入、狩猎收入和家教收入的保护期/观察期默认时长是否按任务类型配置？
- Q-15：提现第一版支持哪些方式，是否需要补充实名或收款账户信息？
