# 佚名 Web 管理系统计划

> 文档状态：Web 平台管理系统架构校准版  
> 更新日期：2026-07-08  
> 当前策略：`admin-plan.md` 只描述 Web 端平台管理系统。该系统仅限平台管理角色登录，用于管理平台信息、审核、对接、复核、配置、风控、订单、售后、举报和数据看板；移动端学生、商户、家长的功能边界由 `client-plan.md` 维护。

## 1. 管理端定位

Web 管理系统服务平台管理角色，第一版重点是把移动端产生的事项处理掉，并沉淀平台基础信息、审核规则和经营治理能力。

平台管理人员核心职责：

- 审核：学生回收、学生校园服务需求、商户商品、商户兼职、家长家教需求、举报内容。
- 对接：回收交付、商户补充资料、商品上架、兼职报名、校园服务需求、家教需求。
- 复核/处理：高风险兼职、异常商品、售后争议、举报、账号冻结、封禁和监管期。

管理入口为独立 Web 登录页，不在移动端客户端内展示。移动端不提供平台管理角色登录入口。

## 5. 审核中心

目标：把所有需要平台确认后才能继续流转的事项集中处理。

审核对象：

- 商户认证
- 商户商品
- 企业/商户中长期兼职
- 商户短期任务兼职
- 家长家教需求
- 学生回收单
- 学生校园服务需求
- 校园动态/评论
- 举报内容

审核动作：

- 通过
- 拒绝
- 要求补充资料
- 转入对接
- 标记高风险
- 下架/关闭

审核详情需要展示：

- 提交人身份：学生/商户/家长
- 提交内容
- 图片或附件
- 风险命中
- 历史记录
- 审核备注
- 对用户可见的拒绝原因

## 6. 对接中心

目标：处理审核之后还需要人工推进的事项。

对接类型：

- 回收对接：约定交付、收货、质检、最终报价、打款。
- 商品对接：商户补充图片、确认库存、确认售后、确认自提点。
- 兼职对接：确认岗位真实性、确认报名方式、处理学生报名异常。
- 家教需求对接：确认孩子年级、科目、授课方式、家教要求和报名对接方式。
- 校园服务需求对接：确认需求、匹配狩猎服务方、跟进完成状态。
- 售后对接：处理退货、退款、商品争议。

对接状态：

- 待对接
- 对接中
- 等待对方回复
- 已完成
- 已关闭
- 异常挂起

## 7. 校园信息管理

目标：统一维护校园基础位置数据，方便学生、商户、家长和平台管理角色在发布信息、筛选信息、审核对接时快速定位。

管理对象：

- 学校
- 校区
- 宿舍楼栋
- 宿舍楼层
- 教学楼
- 食堂
- 图书馆
- 快递站
- 操场/体育馆
- 校门
- 学生活动区域
- 校园周边区域
- 自提点
- 常用位置块

位置块定义：

- 位置块是对学生常活动区域的结构化表达。
- 位置块用于快速选择发布位置，不要求用户每次手写地址。
- 一个位置块可以归属于学校、校区、区域类型和具体楼栋。
- 位置块可以用于回收交付、校园服务需求、商户商品自提、兼职工作地点、平台对接。
- 用户发布信息时优先从管理端维护的区域和位置块中选择；列表没有覆盖时，允许自定义填写位置。

位置块示例：

- 1 号宿舍楼
- 1 号宿舍楼 3 层
- 南区快递站
- 东门
- 图书馆一楼
- 一食堂门口
- 操场看台
- 学生活动中心
- 教学楼 A 区
- 市区带回集合点

能力：

- 学校管理
- 校区管理
- 楼栋管理
- 楼层管理
- 活动区域管理
- 自提点管理
- 常用位置块管理
- 设置位置别名
- 设置位置启用/停用
- 设置位置排序和推荐权重
- 设置位置适用场景
- 查看发布时自定义填写的位置
- 将高频自定义位置沉淀为常用位置块

适用场景：

- 学生注册后补充宿舍楼栋和楼层。
- 学生提交回收时选择交付位置。
- 学生发布校园服务需求时选择起点、终点、集合点。
- 商户发布商品时选择自提点或服务区域。
- 商户发布兼职时选择工作地点。
- 平台管理人员审核和对接时快速识别位置。

位置状态：

- 启用
- 停用
- 待补充
- 合并至其他位置

管理原则：

- 学校和校区是一级基础数据。
- 楼栋、楼层、活动区域、自提点都必须归属到具体校区。
- 位置块名称要短，方便移动端选择。
- 支持别名，解决学生口语叫法和正式名称不一致的问题。
- 高频位置优先展示，降低发布信息时的输入成本。
- 自定义位置只作为兜底输入，管理端需要保留原文，方便审核、对接和后续标准化。

## 8. 学生管理

能力：

- 学生列表
- 学生详情
- 学校/校区筛选
- 宿舍楼栋/楼层查看
- 学生认证状态
- 回收记录
- 购买订单记录
- 兼职报名记录
- 校园服务需求发布记录
- 举报与被举报记录
- 禁言
- 封禁
- 冻结账号
- 解冻账号
- 查看违约金/赔偿处理状态
- 设置监管期
- 解封

学生状态：

- 正常
- 待认证
- 禁言中
- 冻结中
- 监管期
- 封禁中
- 风险用户

学生权限规则：

- 正常状态下，学生可以购买、提交回收、报名兼职、发布校园服务需求和开启狩猎。
- 禁言中，学生可以登录和浏览，但无法发布、评论、发布校园服务需求、开启狩猎或接单。
- 冻结状态下，学生登录后默认跳转解冻申请页，不可购买、发布、报名、接单、提交回收、提现或使用服务能力，仅保留查看处理结果、申诉、缴纳违约金/赔偿和申请解冻入口。
- 监管期状态下，学生可以登录和浏览基础内容，但无法买卖、狩猎或提现，包括购买优选、提交回收、发布校园服务需求、接受委托和发起提现。
- 封禁中，禁止登录学生端或使用学生能力。

## 9. 商户管理

目标：管理商户身份、认证审核和发布权限。商户必须认证审核通过后，才能发布商品和兼职。

商户类型：

| 类型 | 管理说明 |
| --- | --- |
| 校园店铺 | 校内或校园周边稳定经营店铺，重点核验门店照片和经营范围 |
| 个人商户 | 个人经营或轻量服务供给主体，重点核验营业执照、联系人和服务说明 |
| 校外服务商 | 校外面向校园提供服务或商品的主体，重点核验经营范围和服务校区 |
| 校企合作 | 校企、社团、学校或平台合作主体，重点核验合作说明和经营资质 |

统一认证资料：

- 营业执照
- 门店照片
- 商户名称
- 商户类型
- 联系人
- 联系方式
- 经营说明

能力：

- 商户列表
- 商户详情
- 商户认证审核
- 认证资料补充
- 认证通过
- 认证拒绝
- 商品发布记录
- 兼职发布记录
- 门店列表
- 门店详情
- 门店状态管理
- 员工子账号列表
- 员工子账号权限管理
- 员工子账号停用/启用
- 员工子账号密码重置
- 对接记录
- 被举报记录
- 暂停发布
- 恢复发布
- 冻结商户
- 解冻商户
- 查看违约金/赔偿处理状态
- 设置监管期
- 封禁商户

商户认证状态：

- 待提交
- 审核中
- 需补充
- 通过
- 拒绝
- 冻结
- 监管

认证审核处理：

- 待提交状态下，商户尚未提交完整营业执照和门店照片，不进入审核队列。
- 审核中状态下，管理端可查看商户类型、营业执照、门店照片、联系人、联系方式和经营说明。
- 需补充状态下，管理端必须填写补充说明，商户端展示补充原因并开放修改和重新提交。
- 通过状态下，商户获得发布商品、服务和兼职的能力。
- 拒绝状态下，管理端必须填写拒绝原因；商户可修改资料后重新提交，也可进入平台对接入口。
- 冻结状态下，商户不可使用商户服务能力，仅保留解冻申请、申诉和违约金/赔偿处理入口。
- 监管状态下，商户可以登录查看历史内容和消息，但不可新增发布或参与新的交易流转。

发布权限规则：

- 待提交、审核中、需补充、拒绝状态下，商户不能发布商品和兼职。
- 通过状态下，商户可以发布商品、中长期兼职和短期任务兼职。
- 暂停发布状态下，保留商户账号，但禁止新增发布。
- 冻结状态下，商户登录后默认跳转解冻申请页，不可使用商户服务能力，仅保留查看处理结果、申诉、缴纳违约金/赔偿和申请解冻入口。
- 监管状态下，商户可以登录和查看基础内容，但无法买卖、提现或参与新的发布流转，包括发布商品、上架/售卖商品、发布兼职。
- 封禁状态下，禁止登录商户端或使用商户能力。

商户详情需要展示：

- 商户名称
- 商户类型
- 联系人
- 联系方式
- 经营说明
- 营业执照
- 门店照片
- 门店列表
- 认证状态
- 认证补充说明/拒绝原因
- 发布商品数
- 发布兼职数
- 审核通过率
- 举报记录
- 平台备注

商户多门店管理规则：

- 商户认证通过后，可配置多个门店。
- 管理端需要展示商户下所有门店，并查看门店名称、门店编号、所属校区、位置块、自定义地址、联系人、联系电话、营业时间、支持配送方式和门店状态。
- 门店状态包括正常、暂停营业、隐藏、关闭。
- 商户商品管理默认以“全部门店”汇总销售、配送和消息数据。
- 商户筛选单个门店后，商品管理统计、销售列表、配送列表、消息列表和商品卡片列表只展示该门店数据。
- 商品、订单、配送、消息和商户兼职需要记录所属门店。
- 门店暂停营业后，该门店商品不可新增上架；已产生订单继续履约。
- 门店关闭后，不再作为新增商品、订单、配送或兼职发布的可选门店；历史数据保留。
- 管理端在处理订单、配送、售后、举报和数据看板时，需要支持按门店筛选。

商户员工子账号管理规则：

- 商户可创建员工子账号，默认账号格式为 `{账号}@{商户名}`。
- 子账号密码由商户创建或重置时设置。
- 商户账号区分主账号和子账号；主账号拥有商户端全量内容查看和全量操作能力。
- 子账号定位为商户运营成员使用的运营子账号，仅可处理售后、产品咨询、商品管理与维护。
- 子账号不可查看或操作商户认证资料、资金提现、员工子账号、商户兼职发布/招募、全量经营数据和账号状态处理。
- 管理端需要展示子账号所属商户、登录账号、账号类型、权限范围、状态、最近登录时间、创建人和创建时间。
- 商户主账号冻结、监管或封禁时，所属员工子账号同步受限。
- 子账号对商品维护、产品咨询、订单相关咨询和售后的操作需要记录操作人，便于售后争议和平台复核。

家教招募流转规则：

- 学生报名后，家长端已发布的家教招募卡片展示报名成员信息。
- 家长查看学生资料、交换电话或信息沟通时，管理端保留资料查看、电话交换和沟通记录。
- 家长拒绝报名学生时，管理端记录拒绝理由、拒绝时间和对应报名记录。
- 家长选择某个学生后，确认招募按钮可用；家长确认招募后，家教招募进入教育服务中。
- 家教完成后，由学生端发起完成家教服务。
- 教育服务中，如家长或学生一方发起终止或改约并涉及费用变化，管理端记录发起方、原因、实际服务时间、费用结算方案和另一方确认结果。
- 家长端确认结束后，家教招募进入已结束。
- 已结束后，家长和学生可互相评价；评价和举报记录进入管理端可追踪范围。
- 已结束后，家长可收藏本次被确认招募的优秀学生，管理端记录收藏来源、关联家教需求和报名记录。
- 平台开始将费用结算至学生监管账户；监管账户按保护期/观察期账户规则处理，期间不可立即提现。

家教费用管理第一版最短链路：

- 家长确认招募时支付本次家教费用至平台托管账户。
- 家长发起家教时可选择是否试课；选择试课时记录试课时长和试课费用。
- 试课按普通家教需求处理，试课费用按本次需求托管和结算；周期课第一版拆分为单次或阶段需求。
- 家教结束由学生发起完成，家长确认后开始结算。
- 结算金额进入学生保护期/监管账户，保护期结束且无争议后释放。
- 改约、终止或爽约需要一方发起，另一方确认后才可结束对应操作。
- 家教服务中一方终止或改约时，可由发起方同步发起费用结算；另一方确认后，系统按实际服务天数占比支付给学生并退还家长剩余金额。
- 第一版费用计算规则：应付学生金额 = 托管家教费用 × 计费服务天数 / 约定服务天数；应退家长金额 = 托管家教费用 - 应付学生金额。
- 计费服务天数按实际服务时间折算：不满半天按半天，超过半天按一天；多日服务按每天折算后累加。
- 管理端需要记录约定服务天数、实际服务天数、计费服务天数、结算比例、应付学生金额、应退家长金额、双方确认时间和资金流水。
- 第一版暂不考虑家教争议举证和赔付链路；管理端只记录异常状态、双方确认结果和平台联系入口。

商户商品快捷操作管理规则：

- 上架用于允许商品被购买；下架用于停止购买，下架操作需要二次确认。
- 下架商品不可被购买，但是否可查看详情由隐藏状态决定。
- 隐藏用于控制商品是否可被查看；隐藏商品不可查看详情，不进入普通列表、搜索和推荐。
- 本阶段默认隐藏后不可购买且不可查看详情。

- 只填写售卖结束日期时，审核通过并上架后立即可售，到达结束日期后停止售卖。
- 同时填写开始和结束日期时，开始日期不得晚于结束日期。
- 管理端需要记录库存、限购、售价和售卖时间字段的变更记录，用于后续订单争议、售后和商户信用核查。

- 发布和取消发布只控制兼职招募需求是否开放报名，不删除历史信息。
- 招募结束后，当前招募信息进入历史招募列表，后续仍按完成确认、结算、评价和举报流程处理。
- 编辑用于快速编辑招募信息；涉及薪资、结算、人数、人员要求或信息收集表等关键字段时，需要按规则重新审核或进入待对接。
- 发布方发布兼职时必须填写结算规则和人员要求表单。
- 结算规则由商户发布方选择：项目结束时立即结算，或项目结束后 N 天结算。
- 人员要求表单支持快捷按钮：无要求、限性别；选择限性别时必须明确性别要求，但不需要提交平台审核理由。
- 兼职金额统一从平台流转，发布方发布时先支付金额至平台托管账户。
- 商户入驻后，开始销售商品/服务或发布兼职前，需要缴纳店铺信用金；第一版管理端只校验是否已缴纳，不展开复杂扣罚规则。
- 发布兼职时，发布者可选启用签到保证金，并填写签到保证金金额。
- 启用签到保证金后，学生报名时需要缴纳签到保证金；学生完成签到后，签到保证金立即退还。
- 学生忘签到或未签到时，可发起签到保证金退还申请；由兼职发起者确认，24 小时内未确认则自动退还给学生。
- 发起者拒绝退还并投诉时，进入平台介入处理；第一版只保留处理入口、处理状态和通知。
- 发布方在发布管理 - 兼职详情中查看报名人员并筛选确认。
- 发布方确认报名成功名单后，系统将报名成员报名时填写的字段通过邮件发送给发布方，邮件发送记录需要进入管理端可追踪。
- 邮件字段按报名表配置和学生提交内容生成。
- 身份证号、身份证照片等身份证信息不随邮件发送；如需展示身份核验情况，仅展示脱敏或验证状态。
- 邮件发送后，后续由发布方直接对接报名成功人员。
- 不允许超额报名时，报名人数达到招募人数后自动停止报名，兼职进入已招满或停止报名状态。
- 允许超额报名时，报名人数可超过招募人数，发布方必须在报名人员中手动确认最终人员。
- 被确认的报名者未签到、无故不到或签到后拒绝履约，会影响学生信用分并可能扣押金。
- 发布方确认后未聘用、虚假岗位或恶意筛选，会影响发布方信用，必要时触发店铺信用金处理或进入平台复核。
- 兼职完成后，发布方通过我的发布进入发布详情进行项目完成确认。
- 项目结束时间后一周内发布方未确认结束的，系统自动完成项目结束确认。
- 项目结束确认后，平台按确认报名成员生成结算明细，并结算至每个成员账户。
- 项目结束后，发布方和参与者都可在我的 - 兼职中进行评价或举报，举报进入举报中心。
- 支付异常、退款、争议复核、信用分影响事件和押金处理与优选下单保持一致，并保留处理原因、关联报名记录和处理人。

- 管理端只保留异常反馈、举报/投诉和平台联系记录，不展开举证、判责、赔付、押金扣退等完整争议链路。

- 服务发布中，超过时效被领取后，发起者未确认激活前不进入履约；确认激活后出现履约异常，第一版进入平台对接，不做自动判责。

- 系统针对已结束服务开始金额结算。

- 结算金额先进入观察期；观察期内不可提现。
- 观察期结束且无投诉或风控命中后，金额进入服务方钱包可提现余额。
- 第一版不因普通异常自动冻结、扣减或延后结算；完整争议逻辑后续补充。

- 涉及高价值物品
- 涉及隐私或账号
- 地址不清晰
- 酬劳异常

## 14. 狩猎服务方管理

目标：管理委托/狩猎场景中的服务方侧，即学生作为服务方上线后的任务实时分发和接单状态。

核心概念：

- 狩猎中学生：已点击狩猎按钮并处于上线状态的学生。
- 狩猎资格：学生先完成学生认证，再完成身份证实名验证、学籍信息验证并缴纳 100 元押金后获得的服务方资格。
- 狩猎押金：学生开启狩猎前从账号钱包缴纳的 100 元保证金，用于守约约束、赔付和违规处理；缴纳、冻结、扣减和退还均记录钱包流水。
- 狩猎信用分：学生作为服务方的信用评分，初始 10 分，影响可接单额度和推送优先级。
- 可接单额度：由信用分决定的单笔任务预算/酬劳上限。
- 狩猎任务推送池：可实时推送的学生校园服务需求、商户短期任务兼职和平台临时任务。
- 接单响应：学生收到实时消息后的查看、报名、接单或忽略行为。

- 查看信用分机制配置占位
- 查看狩猎任务推送池
- 查看实时推送记录
- 查看接单/报名响应
- 查看接受服务发布和报价发布报价记录
- 查看委托时效、过期状态和超过时效领取后的发起者确认激活状态
- 查看锁单状态
- 查看取消窗口和协商取消状态

| 身份证实名验证 | 人工审核姓名、身份证号和身份证照片 | 身份验证通过 |
| 学籍信息验证 | 人工审核学校、校区、学号/学生证等信息和学信网截图 | 学籍验证通过 |
| 押金缴纳 | 确认 100 元押金到账 | 押金状态为已缴纳 |
| 初始信用分 | 系统发放初始 10 信用分 | 学生获得狩猎信用分基础值 |

信用分机制：

- 信用分影响可接单额度和推送优先级。
- 具体信用分档位、增减规则、可接单额度和影响范围后续单独补充专项机制，当前管理端文档不展开详细数值。
- 评价、守约情况、狩猎次数、完成质量、投诉/争议和风控记录仅作为候选影响维度。
- 当前阶段管理端只要求保留信用分影响事件、关联订单/任务/投诉和操作日志，便于后续接入信用分机制。

推送规则：

- 学生校园服务需求发布后系统默认通过并进入狩猎池；高风险任务可进入后置风控、人工对接或暂停推送。
- 狩猎池内任务默认先到先得，在线狩猎成员可主动接受。
- 系统也可将任务定向分配给在线狩猎成员。
- 优先匹配同校区、相近位置块、任务类型匹配、当前狩猎中的学生。
- 只向完成学生认证、狩猎资格且押金正常的学生推送。
- 任务额度不得超过后续信用分机制配置的当前可接单额度。
- 同等匹配条件下，可按后续信用分机制配置调整推送优先级。
- 高风险任务可后置标记并暂停推送，具体拦截规则后续由配置中心控制。
- 无人响应任务进入平台对接待办。
- 学生下线后不再接收实时短期任务。
- 学生可选择狩猎结束时间，允许跨天且不做最长时长限制；未选择时，默认次日 0 点自动下线。
- 到达狩猎结束时间后，系统自动停止实时推送。

接单与锁单规则：

- 接单列表需展示最晚送达时间、委托费、地点、委托内容、紧急程度、发布模式、委托时效、过期状态和是否需要发起者确认激活。
- 发布方可以设置委托时效。
- 服务发布：未超过委托时效时，服务方接受后立即激活并锁定；超过时效时仍可领取，但领取后先推送给发起者确认是否激活。
- 发起者确认激活后，领取生效并进入委托进行中；发起者拒绝或超时未确认时，领取不生效。
- 报价发布：服务方提交报价后等待发起者选择并确认，报价本身无有效期。
- 报价结束条件：发起者确认某个报价、发起者拒绝报价、委托被关闭。
- 发起者确认报价后，委托激活并进入进行中状态，他人不可再领取或报价。
- 发起者拒绝报价后，该报价记录结束；若发起者关闭本次委托，则他人不可再领取或报价，仍需服务时由发起者再次发布。
- 接受委托后 2 分钟内，接受者可以自助取消。
- 接受委托后 5 分钟内，接受者可发起协商取消，需发布方确认。
- 超过可取消窗口、未经确认取消或造成超时/履约影响的，记录信用分影响事件；具体分值后续随信用分机制补充。
- 同一时间允许接受多份委托；同时接受的委托越多，若发生超时，信用分影响越大。
- 推送频率、单位时间推送数量等推送限制规则本阶段暂不补充。

狩猎状态：

- 未上线
- 狩猎中
- 忙碌中
- 多单中
- 已下线
- 风险暂停

推送状态：

- 待推送
- 已推送
- 已读
- 已报名
- 已接单
- 已报价
- 报价待确认
- 已锁单
- 取消协商中
- 已忽略
- 已超时
- 推送失败

风险关注：

- 学生频繁接单后取消
- 学生长期在线但无响应
- 同一任务多次无人响应
- 押金不足或押金被扣减后继续接单
- 信用分异常升降
- 高风险地点或高风险物品
- 任务酬劳异常

## 15. 资金账户管理

目标：管理学生作为服务方获得收入后的账户流转、保护期/观察期、提现和争议处理。

账户类型：

- 可提现钱包：已过保护期/观察期、可发起提现的余额。
- 保护期账户：任务完成后进入保护期或观察期的待结算额度，期间不可立即提现。
- 冻结金额：因争议、投诉、风控或提现异常暂时不可用的额度。

入账来源：

- 学生校园服务需求完成收入。
- 狩猎接单完成收入。
- 企业/商户中长期兼职完成确认后的平台结算收入。
- 商户短期任务兼职完成收入。
- 平台临时任务完成收入。
- 家长家教招募完成并由家长确认结束后的家教服务收入。

保护期/观察期规则：

- 任务完成确认后，收入先进入保护期账户。
- 校园服务需求在发布者确认服务结束后开始结算，金额先进入观察期。
- 保护期/观察期按任务类型配置，当前统一默认 3 天。
- 保护期/观察期内不允许提现。
- 保护期/观察期结束且无争议，系统自动转入可提现钱包。
- 出现投诉、退款、争议或风控命中时，可冻结保护期额度。
- 平台处理争议后，可释放、扣减或延后解锁。

能力：

- 查看学生钱包
- 查看钱包记录
- 按钱包记录类型筛选：全部、收入、支出、退款、提现、冻结、解冻、押金、保证金、结算、扣减
- 查看可提现余额
- 查看保护期余额
- 查看观察期余额
- 查看冻结余额
- 查看保护期入账明细
- 查看观察期入账明细
- 手动释放保护期额度
- 冻结/解冻保护期额度
- 扣减争议金额
- 查看提现申请
- 查看提现方式：支付宝、银行卡号
- 审核提现申请
- 标记提现成功/失败
- 查看账户流水

钱包记录第一版：

- 管理端需要记录收入、支出、冻结、解冻、扣减、退还、退款、结算、提现、押金、保证金等钱包流水。
- 钱包详情支持按类型筛选，记录发生时间、金额、类型、关联业务、状态和备注。
- 第一版只做记录查看和类型筛选，不展开复杂资金对账、手工调账和跨渠道退款拆分规则。

提现状态：

- 待审核
- 审核通过
- 打款中
- 已打款
- 提现失败
- 已驳回

保护期入账状态：

- 保护期中
- 已释放
- 已冻结
- 已扣减
- 延后释放

风险关注：

- 频繁提现失败
- 同一学生多次争议
- 任务完成后立即投诉
- 异常高额任务收入
- 保护期内重复取消或退款

配送/履约方式：

| 方式 | 管理重点 |
| --- | --- |
| 物流/快递 | 物流费、预计送达时间、联系电话、物流状态；家长商品订单唯一履约方式 |

| 线上交付 | 交付方式、交付凭证、完成确认 |

家长商品订单规则：

- 家长端商品订单只允许快递配送。
- 管理端订单列表需要支持按买方身份筛选学生订单和家长订单。
- 家长订单详情需要展示收货地址、收件人、联系电话、物流公司、物流单号、物流费、发货时间和预计送达时间。
- 家长订单不进入自提、小时达、立刻配送、指定时间配送、到店服务或预约服务履约流转。
- 商户或平台商品如未配置快递配送，不应出现在家长端可购买列表；管理端商品审核和上架时需要能检查该配置。

商户配送处理规则：

- 商户端配送列表默认展示待配送订单。
- 商户点击开始配送后，可选择物流或人工配送。
- 选择物流时，商户需填写物流单号；提交后订单进入配送中状态。
- 选择人工配送时，商户确认提交后订单进入配送中状态。
- 配送中订单由商户点击完成后进入待确认状态，商户端完成按钮置灰。
- 待确认状态下，需等待用户端确认收货或确认完成。
- 用户端确认后，配送订单进入已完成状态。
- 管理端订单详情需记录商户配送方式、物流单号、开始配送时间、商户完成配送时间和用户确认时间。

订单/配送调整诉求规则：

- 用户端发起订单调整诉求后，商户销售订单卡片展示诉求按钮。
- 用户端发起配送调整诉求后，商户配送卡片展示诉求按钮。
- 商户点击诉求按钮后，可查看诉求类型、用户说明、原信息、期望调整信息、发起时间和联系方式。
- 商户可选择同意或拒绝。
- 同意后，管理端记录商户同意时间、处理人和诉求状态。
- 拒绝后，管理端记录拒绝结果；拒绝原因是否必填后续可配置。
- 诉求处理结果需要同步给用户端订单消息。
- 管理端订单详情需要可追踪订单调整诉求和配送调整诉求的历史记录。

费用明细：

| 费用项 | 说明 |
| --- | --- |
| 产品金额 | 商品/服务基础金额，按数量计算 |
| 服务费 | 平台服务、对接或即时履约费用 |
| 物流费/配送费 | 根据履约方式、距离、校区或配置计算 |
| 优惠金额 | 平台优惠、活动或补贴 |
| 应付总额 | 用户最终提交支付金额 |

- 管理端订单详情需要记录支付方式、组合付款拆分金额、渠道流水号、余额扣减流水和支付异常状态。

预约服务取消扣款规则：

- 预约服务的取消扣款规则在管理端配置，可按商户服务、服务分类或平台默认规则维护。
- 订单生成时保存取消规则快照，后续后台规则调整不影响已生成订单。
- 学生从订单详情取消预约服务时，系统按规则快照计算扣款金额和退款金额；家长商品订单不进入预约服务取消规则。
- 管理端需可查看取消时间、规则命中结果、扣款金额、退款金额和处理人。
- 服务开始后、争议中或售后中的订单，不走普通取消，进入售后或人工处理。

优选售后审核规则：

- 优选订单送达、确认收货或服务完成后，不支持学生或家长自助直接退款。
- 平台自营产品、自营耗材和平台自营闲置，由平台人工接入售后处理。
- 后续入驻商户的商品或服务，由商家自行售后处理；平台管理端保留售后记录、商家处理状态和投诉复核入口。
- 平台不直接替商家处理普通售后退款，只围绕投诉情况进行人工复核，并记录信用分影响、举报治理或账号限制依据。
- 管理端人工复核投诉时，需要查看订单、商品/服务、配送/履约记录、证据材料、历史售后和举报记录。
- 平台自营产品经人工接入确认后，可标记支持退款申请、部分退款、退货退款、补偿或平台对接处理。
- 退款发起后原则上实时到账，最晚 2 个工作日到账；退款异常进入订单消息、我的入口和管理端支付/退款异常记录。
- 证据审核标准、人工介入流程和人工赔付边界暂不在本阶段细化，仅保留投诉、复核和处理结果记录入口。
- 商家入驻产品的售后处理结果由商家维护；若学生或家长投诉商家处理异常，平台复核后记录处理结论和信用分影响事件。
- 信用分具体档位、增减规则和扣分细则后续单独补充，当前管理端只记录影响事件和关联投诉。

违规账号处理规则：

- 举报审核确认违规后，关联违规账号进入冻结状态。
- 冻结状态下，账号登录后默认跳转解冻申请页，不可使用平台产品服务能力，仅保留查看处理结果、申诉、缴纳违约金或赔偿、申请解冻的入口。
- 管理端可根据违规类型设置违约金、赔偿金额或二者同时存在。
- 用户完成违约金或赔偿后，平台复核确认，账号可解冻。
- 解冻后自动进入 1 个月监管期。
- 监管期内无法买卖、狩猎或提现；再次违规可重新冻结或升级为封禁。
